# Исправления прошивки DDS 1.0.1 и результаты проверки

Дата: **06.11.2026**. Плата F. Изменения относительно `aec5cb5` (документация и код 1.0.0). Все четыре пункта [REMARKS.md](../firmware/REMARKS.md) обработаны в коде; электрические проверки остаются открытыми.

## Что изменено

| Замечание | Реализация | Проверка |
|---|---|---|
| Одиночное несовпадение CTR вызывает сброс | До трёх чтений по маске `0x701F`; любое правильное завершает проверку. Три неправильных, в том числе разных, дают VERIFY | Одиночная ошибка, каждый определённый бит, резерв, чередование, сброс DDS, ошибки SPI/PGOOD |
| Накопленные тики повторяют один замер | Один замер на опрос; при пропуске сброс незавершённого подтверждения. В WAIT_POWER высокий PGOOD подтверждается заново | Короткий импульс после 255 тиков, пропуск посреди удержания, дребезг, восстановление питания |
| Неточная строка о 1 МГц | `8 MHz calibration missing; run 'osccal' target`; UBRR не меняется по факту отсутствия калибровки | Все 256 корректных пар EEPROM, пустая и повреждённая память; сообщения в настоящем AVR ELF |
| Контроль PGOOD только в RUN | Сырой PC4 в каждом опросе, до/после каждого кадра SPI и через 1 мс при ожидании DIP; отключение до UART-лога | Все состояния автомата, каждый кадр запуска, ожидание DIP, провал внутри кадра в simavr |

Низкий PGOOD отключает DDS без программной фильтрации. Перед включением высокий уровень подтверждается 10 мс, затем выдерживается пауза 20 мс. При потере питания драйвер возвращает POWER; приложение переходит в WAIT_POWER и сохраняет последнюю частоту в ОЗУ для восстановления.

Маска CTR соответствует [ТО ЭЛВИС 1508ПЛ8Т, таблица 5.3](https://elvees.ru/mc/data_sheets/Manual_1508PL8T.pdf): учитываются компаратор, оба ЦАП и cmx; остальные биты зарезервированы. Самостоятельно меняющихся флагов в этой таблице нет.

CKSEL выбирает номинальную частоту RC, OSCCAL корректирует её. Пустая EEPROM не меняет CKSEL на 1 МГц. Основание — [ТО 1887ВЕ7Т](<../info/1887BE1T/Руководства по эксплуатации/ТО 1887ВЕ7Т.pdf>), раздел 3.3.7 и стр. 300. Этим исправлено неточное объяснение первоначального замечания 3.

## Выполненные проверки

| Проверка | Результат |
|---|---|
| AVR Debug, avr-gcc 5.4.0, ATmega128, 8 МГц | Успешно; flash 6578 байт, статическая SRAM 130 байт |
| AVR Release, тот же компилятор | Успешно; flash 5306 байт, статическая SRAM 55 байт |
| `dds_core_tests` | 5190 проверок, 0 ошибок |
| `dds_firmware_tests` | 1239 проверок, 0 ошибок |
| `sim_dds` | Успешно: 12 сценариев, корректная калибровка EEPROM |
| `sim_dds_empty_cal` | Успешно: те же сценарии с пустой EEPROM |
| `sim_dds_invalid_cal` | Успешно: те же сценарии с повреждённой парой EEPROM |
| Итог CTest | 5 из 5 наборов прошли |

Компиляция C прошла без предупреждений. CMake предупредил об отсутствии avrdude в проверочной среде: цели аппаратного программирования там не создавались и запись контроллера не выполнялась. Размер SRAM — `.data + .bss`, без стека.

Новые тесты запускают производственные `app.c`, `pl8t.c`, `board.c`, `osccal.c` и функции ядра. На ПК подменены только регистры МК, SPI, EEPROM и время. Дополнительно simavr исполняет собранный Debug ELF с реальными драйверами SPI и Timer0, моделью регистров DDS и внесением ошибок в обмен. Release собран; симуляция проводится на Debug.

Базовые тесты и тесты приложения также прошли с MinGW GCC 7.3 на Windows. Финальный прогон после последней правки выполнен в WSL GCC 11.4/avr-gcc 5.4. Инструменты AVR и simavr распакованы в локальный `firmware/build/toolchain`; содержимое `build/` исключено из Git. Незавершённая установка пакетов WSL не исправлялась и не использовалась для установки этих инструментов.

## Как повторить

При установленном тулчейне и зависимостях, из папки `firmware`:

```sh
cmake --preset avr-debug
cmake --build --preset avr-debug
cmake --preset avr-release
cmake --build --preset avr-release
cmake --preset sim
cmake --build --preset sim
ctest --preset sim
```

Для проверок на ПК без AVR и simavr:

```sh
cmake --preset host-tests
cmake --build --preset host-tests
ctest --preset host-tests
```

На этой машине использовались отдельные каталоги `build/wsl-avr-debug`, `build/wsl-avr-release`, `build/wsl-sim`, чтобы не смешивать CMake-кэш Windows и Linux. Для нестандартного пути ELF задаётся `DDS_SIM_ELF`.

## Пределы проверки

- Электрические испытания платы не проводились. Подтвердить запись/сверку flash, DEVID, частоты и уровень выхода, UART после калибровки, JTAG через avarice.
- PGOOD — цифровой вход PC4, а не точный супервизор напряжения. Короткий провал между проверками может быть пропущен; UART-вывод задерживает опрос. Начатый SPI-кадр завершается до следующей проверки.
- Отключение D3 через OE# не переводит все выходы МК в высокоимпедансное состояние. Подпитка обесточенного D3 и уровень PC4 при снятой шине требуют аппаратной проверки. +1,8 В отдельно не контролируется.
- simavr не моделирует аналоговые шины питания, реальную частоту RC и ВЧ-тракт DDS; его успешный прогон не закрывает эти пункты.
- Проверка CTR не проверяет весь набор регистров и фактический ВЧ-выход.

Аппаратная ревизия F и архивы старых ревизий не изменены. Руководство пользователя и README обновлены под поведение 1.0.1.

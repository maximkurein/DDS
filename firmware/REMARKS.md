# Замечания к прошивке DDS 48–52 МГц

Обновлено: **06.11.2026**. Ревизия платы F, прошивка `dds_fw` 1.0.0, исходники коммита `40b6ebf`. Статический разбор без повторной сборки, симуляции и испытаний на плате.

Это актуальный список замечаний и критериев их закрытия. Обоснования — в [FIRMWARE_REVIEW.md](../docs/FIRMWARE_REVIEW.md), порядок эксплуатации — в [USER_GUIDE.md](../USER_GUIDE.md). Обновление документа не означает исправления кода.

| № | Замечание | Статус |
|---|---|---|
| 1 | Сброс DDS после одного несовпадения CTR | Подтверждено, исправление открыто |
| 2 | Один замер входа учитывается как несколько тиков | Подтверждено, исправление открыто |
| 3 | Неоднозначное сообщение о калибровке RC | Объяснение в документации исправлено; сообщение в коде ещё требует правки |
| 4 | Потеря PGOOD обрабатывается только в RUN | Подтверждено, исправление и аппаратная проверка открыты |

Прошивка собрана аккуратно. Шкала частот, карта регистров 1508ПЛ8Т и распиновка разведены по разным файлам. Смена частоты идёт через два профиля: новое приращение фазы пишется в неактивный, проверяется чтением и включается одной записью в `SEL_REG`. ЦАП включается уже после переключения, так что нулевая частота на выход не попадает. Расчёт приращения фазы и дребезг покрыты тестами на ПК, сценарии изделия — моделью в simavr.

Ниже то, что на первом включении платы может дать ложный отказ или пропадание сигнала.

---

## 1. Одно несовпадение CTR вызывает перезапуск DDS

`pl8t_check_alive()` раз в секунду читает CTR один раз и сравнивает все 16 бит с копией в ОЗУ. Любое отличие — это `FAULT`: сразу RSTn, буфер D3 выключен, пауза `DDS_RETRY_PERIOD_MS` (500 мс), затем полная инициализация.

Для `SEL_REG` используется маска `SEL_PR_MASK`. Для CTR маски и повторного чтения нет. Один ошибочный кадр SPI может вызвать потерю сигнала на 500 мс плюс время повторного запуска. Наличие самостоятельно меняющихся флагов CTR не подтверждено и не должно считаться установленной причиной.

**Что сделать.** Определить по ТО маску контролируемых битов, включая намеренно выключенные функции. Маски только `DAC1_ON | cmx` недостаточно без проверки остальных полей. Ввести ограниченное число повторных чтений: устойчивые или чередующиеся неверные значения должны приводить к отказу за конечное время, даже если два неправильных слова не совпали.

**Критерий закрытия.** Проверить одиночный сбой чтения, устойчивое несовпадение, чередующиеся ошибки и сброс DDS. Зафиксировать допустимую задержку обнаружения и отсутствие лишнего перезапуска при единичной помехе.

## 2. Дребезг ломается, когда цикл простоял дольше порога

Чтение DIP и инициализация DDS блокируют основной цикл. Тики за это время копятся, а `sample_inputs()` снимает уровень один раз и многократно передаёт его в счётчик дребезга:

```c
static void sample_inputs(uint8_t ticks)
{
    const bool pressed = board_apply_pressed_raw();
    const bool pgood = board_pgood_raw();
    while (ticks-- != 0u) {
        if (debounce_update(&s.apply, pressed) && s.apply.state)
            s.apply_event = true;
        if (debounce_update(&s.pgood, pgood) && s.pgood.state)
            s.t_pgood = systick_ms();
    }
}
```

Заданные 20 мс для кнопки и 10 мс для PGOOD после длинной паузы не гарантируют соответствующее время наблюдения входа. Например, 25 накопленных тиков превращают один низкий замер PC4 в 25 одинаковых образцов и могут вызвать отключение выхода.

**Что сделать.** Не считать один замер несколькими независимыми образцами. Выбрать периодическое семплирование либо сбрасывать подтверждение устойчивости после слишком длинного интервала. Один вызов `debounce_update()` на опрос сам по себе не доказывает устойчивость уровня во время пропущенного интервала.

**Критерий закрытия.** Проверить короткий импульс после длительной паузы, устойчивое изменение и обычный дребезг. Тестировать вызовы из приложения, а не только отдельную функцию `debounce_update()`.

## 3. Сообщение об отсутствии калибровки RC вводит в заблуждение

`osccal_apply_from_eeprom()` проверяет пару «байт и дополнение» в EEPROM. Если пары нет, OSCCAL остаётся без изменения, а журнал содержит `factory 1 MHz`. Скорость UART рассчитывается для 8 МГц. Эта строка не измеряет частоту ядра.

По ТО номинальный диапазон RC выбирает CKSEL: `0001` — 1 МГц, `0100` — 8 МГц. При сбросе загружается калибровка для 1 МГц, а для другого диапазона нужен соответствующий байт OSCCAL. После записи Low fuse `0x24` пустая EEPROM не возвращает МК на 1 МГц. Возможна ошибка частоты и UART, но нельзя утверждать обязательное замедление SPI в восемь раз или гарантированный запуск DDS. Основание: [ТО 1887ВЕ7Т](<../info/1887BE1T/Руководства по эксплуатации/ТО 1887ВЕ7Т.pdf>), раздел 3.3.7, стр. 53 и 300.

**Что сделать.** Выполнить фьюзы Debug → `FW: RC 8 MHz calibration → EEPROM` → Flash Debug до проверки UART. Заменить сообщение в `main.c` на описание отсутствующей калибровки 8 МГц. Не пересчитывать UBRR на 1 МГц только по `OSCCAL_MISSING`.

**Критерий закрытия.** Проверить корректную, пустую и повреждённую пару EEPROM; убедиться, что сообщение соответствует состоянию калибровки. На плате подтвердить UART 38400 после записи фьюзов и индивидуальной калибровки. В Release журнал отключён.

## 4. Пока автомат не в RUN, пропадание +3,3 В не обрывает шину

Потеря питания по `!s.pgood.state` обрабатывается только в `APP_ST_RUN`. В `RESET`, `RECOVER` и `INIT` нет общего выхода по потере PGOOD. Инициализация содержит блокирующий обмен SPI; остановка возможна при ошибке обмена или после перехода к проверке в RUN. Немедленное прекращение обмена при снижении питания не гарантируется.

D3 — 1564АП3У2 от +3,3 В, входы от МК с уровнями 5 В подключены через 1 кОм. Выключение выходов D3 через OE# не переводит выходы МК в высокоимпедансное состояние и само по себе не доказывает отсутствие подпитки обесточенного узла.

**Что сделать.** Расширить контроль питания на стадии запуска. Проверять питание между этапами обмена или сделать инициализацию пошаговой: одна проверка перед блокирующей `pl8t_init()` не защищает весь интервал. Отдельно оценить электрическое поведение обесточенного D3 и необходимость изменения состояний выводов МК.

**Критерий закрытия.** Проверить потерю PGOOD во всех стадиях запуска и RUN, ограничение времени отключения и восстановление. На макете измерить PC4 и токи при снижении/отключении +3,3 В: R88 47 кОм подключён к самой контролируемой шине, поэтому устойчивый низкий уровень при высокоимпедансном состоянии шины нужно подтвердить. Шина +1,8 В программой отдельно не контролируется.

## Что проверялось ранее

Ниже — свойства исходников и результаты, зафиксированные в README. В этом проходе тесты не повторялись.

- Приращение фазы считается делением столбиком, без float. Для N = 0…4000 тесты сходятся со вторым, независимым способом. Погрешность округления меньше 1 мкГц.
- Запись регистров проверяется чтением, кадр SPI — 24 бита, режим 0, SCSn поднимается после каждого слова. При такте МК 8 МГц скорость SPI — 62,5 кГц; обоснование ограничения — в [design_notes.md](../docs/design_notes.md).
- Старт сохраняет бит JTD, сторожевой таймер гасится до инициализации `.data`, калибровка 8 МГц лежит в EEPROM парой с дополнением.
- Фьюзы (M103C, CKSEL = 0100, EESAVE, OCDEN отдельно для Debug и Release) сходятся с ТО 1887ВЕ7Т. Заводские `L=0xE1 H=0x99 E=0xFD` (RC 1 МГц и режим ATmega103) в README разобраны.
- Всё, что зависит от изделия, собрано в `config/dds_config.h`.

## Что подтвердить на плате

Все пункты ниже остаются открытыми. Успешная сборка или симуляция не заменяет эти измерения.

1. Страница flash профиля `1887ve7t`: 64 байта в avrdude против 128 слов в ТО МК. Сверка записи — первый практический тест.
2. Устойчивое чтение DEVID = `0x0201` через D4 и сверка записанных регистров. `init: error DEVID` не устанавливает причину однозначно: проверить питание, такт и SPI.
3. Уровень −10 дБм и подбор `DDS_AMPLITUDE_MUL`.
4. Осциллограмма SCK на выходе D3: форма фронтов и уровни при фактической нагрузке и резисторах 1 кОм.
5. CTR в спокойном режиме и при воспроизводимых помехах. Несколько минут без ошибки не закрывают замечание 1; нужны сценарии ошибок из его критерия закрытия.
6. PC4 при снятом +3,3 В: устойчивый 0, а не дребезг входа без подтяжки.
7. Atmel-ICE + avarice с 1887ВЕ7Т: подключение, брейкпоинты, пошаговое выполнение и продолжение работы.

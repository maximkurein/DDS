# Шаблоны записей

## 1. Запись об изменении (ECO)

Хранится в `docs/design_notes.md` в разделе «Ревизия <Y>» (одна запись на пункт). Нумерация: `<Y>-NN` (например, `F-01`).

```
### F-01 <краткое название>
Основание: <замечание заказчика / ошибка D-xx / результат макета / ТУ — со ссылкой, датой>
Тип: T3, T4
Затронуто: D5, C46–C48, R83–R87 (поз. ревизии <Y>); листы: Питание; зона платы: левая часть (x 0–40 мм)
Было → стало: <кратко, с номиналами и корпусами>
Расчёт/обоснование: <таблица «параметр — значение — как получено» или ссылка>
Режим: генератор | ручной доработки
Проверка: ERC 0; сверка (а) IDENTICAL; сверка (б) IDENTICAL; DRC 0/0/0; BOM-diff = только перечисленные позиции
Открытые вопросы: <что остаётся неподтверждённым, кто должен ответить>
```

## 2. Реестр дефектов (найденные ошибки изделия)

Ведётся в `docs/defects.md`, строка на дефект. Дефект закрывается ссылкой на запись ECO.

| ID | Обнаружен | Где (лист/поз./плата) | Описание | Как найден | Серьёзность | ECO | Статус |
|---|---|---|---|---|---|---|---|
| D-01 | макет, 2026-11-05 | D5, вывод 7 | ON_OFF оставлен открытым — запуск зависит от наводок | включение | блокирующий | F-01 | открыт |

Серьёзность: блокирующий (изделие не работает / опасно), существенный (работает с ограничением), косметический (шелкография, текст).

## 3. Строка истории (в `README_RU.md`)

```
| F | <что сделано одной фразой>; <число компонентов>, <число цепей>; <что остаётся заполнителем> |
```

Пример из DDS: «E | отечественные стабилизаторы … и логика …; 175 компонентов, 159 цепей; посадочные места новых элементов — заполнители».

## 4. Раздел `design_notes.md` для ревизии

```
## Ревизия <Y>: <название>
Основание · Таблица соответствия обозначений (было → стало) · Изменения (ECO F-01 …) · Расхождения с исходными данными ·
Состояние проекта (ERC, DRC, число компонентов и цепей) · Открытые пункты (обновлённый список)
```

Старые разделы не удаляй — помечай «закрыт в ревизии <Y>», чтобы сохранялась история решений.

## 5. Сообщение коммита и метка

- Коммит: `Rev <Y>: <что>` + ссылки на ECO в теле. Бинарные выходные файлы — отдельным коммитом «Rebuild outputs».
- Метка: `rev<Y>-baseline` ставится на коммит, на котором ворота пройдены.
- Не коммить и не пушь без просьбы пользователя.

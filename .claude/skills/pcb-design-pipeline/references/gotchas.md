# Грабли (проверено на DDS)

Каждый пункт — то, на чём реально теряли время. Формат: симптом → причина → что делать.

## KiCad Python (`pcbnew`)

- **Итераторы SWIG не повторно входимы.** Один и тот же проход по трассам/переходным в одном процессе после изменения даёт мусор или падение.
  → Каждый шаг чистки платы запускай отдельным процессом (`zero_len.py` вызывается в цикле до кода возврата 0, как в `route_all.sh`).
- **`pcbnew` при выходе перезаписывает `.kicad_pro` без секции схемы.** Теряются нумерация секций (`D1.1`), рамка ГОСТ и список листов;
  после этого нетлист называет `D1A`, а DRC со сверкой схемы сообщает конфликты цепей.
  → После любого скрипта на `pcbnew` запускай `tools/pro_merge.py <проект>`; перед DRC тоже.
- **Скрипты `pcbnew` требуют Python из состава KiCad**, а не системный. Проверка: `$KPY -c "import pcbnew"`.

## kicad-cli и формат файлов

- Сгенерированную схему всегда прогоняй через `kicad-cli sch upgrade --force`, иначе KiCad при открытии предложит конвертацию.
- DRC без `--schematic-parity` не увидит расхождений между схемой и платой — всегда включай ключ.
- ERC/DRC сохраняй в `reports/` и коммить: по изменению отчёта видно, что поменялось в ревизии.

## Разводка

- Freerouting плохо трассирует ВЧ-цепи: ВЧ-линии пиши вручную кодом и фиксируй, для классов CLK/CLK50 ограничивай слой F.Cu.
- `route_all.sh` и `build_all.sh` **разводят и расставляют заново**. Начав править руками — запускай только `make_outputs.sh`.
- Заполнители посадочных мест дают «успешный» DRC, который ничего не говорит о сборке. Зелёный DRC на заполнителях — не готовность к выпуску.

## Windows / macOS / git

- Скрипты `*.sh` запускать из Git Bash: `sh tools/make_outputs.sh .`. `cd` в Bash-вызове может сместить рабочий каталог на следующий вызов — используй абсолютные пути.
- Один и тот же `.kicad_sch` / `.kicad_pcb` не править на двух машинах одновременно: конфликты в них вручную не сливаются. Порядок: `git pull` → работа → `git commit` → `git push`.
- После пересборки на другой ОС бинарные выходные файлы меняются побайтно, а `netlist.xml` может отличаться несколькими служебными строками — это не изменение проекта.
- `git push` с 403 — вход не под владельцем репозитория.

## Документы

- `make_outputs.sh` без пакетов `vsdx`, `python-docx`, `pillow` молча пропускает Visio и Word. Проверяй вывод скрипта на строки `skipped`.
- Visio и Word — производные. Правка руками пропадёт; корректируй источник (поля компонентов, штамп).

## Данные

- Расхождение источников по одному и тому же ЭРИ (документ заказчика и спецификация изготовителя, два корпуса одной микросхемы)
  → не выбирай молча: зафиксируй оба варианта и выбранный в `design_notes.md`, открытый пункт — «подтвердить по ТУ».
- Расчёт по формулам изготовителя проверяй подстановкой в обратную сторону. В DDS так нашли, что порог ограничения тока по документу заказчика фактически отсутствует,
  а время плавного пуска меньше заявленного в сотни раз.

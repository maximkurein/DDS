# Фаза 4: схема электрическая принципиальная (Э3)

Полные правила оформления проекта DDS — `docs/Правила_оформления_Э3_ПЭ3.md`. Здесь только то, что нужно, чтобы вести схему по процессу.

## Как строится схема

`dds_build.py` читает базу компонентов и соединения, и пишет `.kicad_sch` (формат 20250114), символы и рабочий лист ГОСТ.
После записи схема обязательно «нормализуется» `kicad-cli sch upgrade --force` — иначе KiCad откроет её с предупреждениями.

Источники соединений для новой ревизии (в таком порядке приоритета):

1. Нетлист предыдущей ревизии (`verification/netlist_revX.xml`) — для неизменённых узлов.
2. Правки ревизии (`eco.py`: `REMOVED`, `REPLACED`, `NETS`) — для изменённых.
3. Для первой ревизии нового изделия нетлиста-предшественника нет: заведи заданные соединения явно
   (`verification/expected_*.json` формата `{цепь: [[поз, вывод], ...]}`) и считай их эталоном.

## Оформление (кратко)

- Листы: сигнал слева направо, питание — символами питания, межлистовые связи — глобальными метками с одинаковыми именами.
- Позиционные обозначения по ГОСТ 2.710: D (микросхемы), C, R, L, VD, G, S, X, XW, F. Нумерация сквозная: слева направо, сверху вниз, лист за листом.
  Секции — `D1.1`, `D1.2` (в проекте: `subpart_id_separator = 46`, `subpart_first_id = 49` — это коды символов `.` и `1`).
- УГО по ГОСТ 2.743 / 2.728 / 2.723 / 2.730 / 2.755; многосекционные микросхемы — частями.
- Рамка и штампы — `lib/GOST_E3.kicad_wks` (форма 1 на первом листе, 2а на остальных). Поля штампа заполняются из блока заголовка листа
  (`${COMMENT1}` обозначение, `${TITLE}` наименование и т. д.).
- Децимальный номер, фамилии, организация — данные заказчика; до получения оставляй `ХХХХ.ХХХХХХ.ХХХ` и пустые графы. Литеру не ставь.
- Неподключённые выводы — крест (no-connect). Всё на сетке 1,27 мм.
- Неподтверждённые узлы — пометка «НЕ ПОДТВЕРЖДЁН», выводы «?» (пример: G1).

## Ворота фазы 4

```sh
kicad-cli sch export netlist --format kicadxml -o output/netlist/netlist.xml <root>.kicad_sch
kicad-cli sch erc --severity-all -o reports/ERC.rpt <root>.kicad_sch
python tools/netcompare.py --expected verification/expected_revX.json output/netlist/netlist.xml
python tools/netcompare.py --ignore-values --refmap verification/refmap_revW_to_revX.json \
       --exclude-a <изменённые поз. ревизии W> --exclude-b <новые поз. ревизии X> \
       verification/netlist_revW.xml output/netlist/netlist.xml
```

Ожидаемо: ERC — 0 ошибок и 0 предупреждений; обе сверки — `IDENTICAL`. Список исключаемых позиций берётся из `verification/eco_revX.json`
(его пишет генератор), вручную его не составляй. `build_all.sh` делает всё это автоматически и показывает последнюю строку каждой сверки.

Если сверка показывает `DIFFERENT`, разберись по строкам `net only in A/B` и `components only in A/B`:
- цепь только в A — потеряна связь или переименован вывод;
- цепь только в B — лишняя связь (часто из-за ошибки в `eco.py` или неверного `refmap`).
Не «лечи» сверку расширением списка исключений, пока не понял причину.

## Типичные ошибки

- Пересечение четырёх линий в одной точке — заменить T-соединениями с точкой.
- Вывод не на сетке 1,27 мм → цепь «висит» визуально соединённой, но ERC ругается. Привязка выполняется функцией `snap` в `kisch.py`.
- Размер шрифта на схеме меньше образца заказчика (1,27–1,8 мм вместо 2,5 мм): сознательное решение «три листа A2/A3»; если заказчик требует 2,5 мм, нужно менять размеры в `gost_symbols.py` / `sheet.py` и переходить на A1.

# 1887ВЕ7Т: проверенная сводка и программирование в проекте DDS

Уточнено 05.11.2026 по документам, добавленным в `info/1887BE1T`. Несмотря на имя каталога `1887BE1T`, документы и эта сводка относятся к **1887ВЕ7Т**. Состояние проекта: ревизия E, D2 — 1887ВЕ7Т. Проверены файлы проекта и документы; подключение к физическому микроконтроллеру не выполнялось.

## 3. Основные параметры и питание

| Параметр | Подтверждённое значение |
|---|---|
| Ядро | 8-разрядное AVR RISC, 32 рабочих регистра, аппаратный умножитель |
| Частота | До 16 МГц при допустимом питании; установленная частота определяется фьюзами и источником такта |
| Память программ | 128 КиБ = 64К 16-разрядных слов; байтовые адреса 0x00000…0x1FFFF |
| SRAM / EEPROM данных | 4 КиБ / 4 КиБ |
| Периферия | SPI, TWI, 2 USART, 2 восьмиразрядных и 2 шестнадцатиразрядных таймера, 8-канальный 10-разрядный АЦП, watchdog, JTAG |
| Питание цифровой и аналоговой частей | 4,5…5,5 В; разность между ними не более 0,3 В |
| VCC / GND | VCC: 21, 52; GND: 22, 53 |
| AVCC / AGND / AREF | 64 / 63 / 62; AVCC питает также порт F, поэтому нужен и при использовании JTAG без АЦП |
| Обычные цифровые входы | VIL ≤ 0,2·VCC; VIH ≥ 0,6·VCC; исключения BQ1 и RESET ниже |
| BQ1 | VIL ≤ 0,1·VCC; VIH ≥ 0,7·VCC |
| RESET# | VIL ≤ 0,2·VCC; VIH ≥ 0,85·VCC |
| Выходы при VCC=4,5 В и токе 20 мА | VOH ≥ VCC−1,2 В; VOL ≤ 0,7 В |
| Активный ток | Не более 50 мА при VCC=5,5 В, f=8 МГц; это не норма для 16 МГц |
| Температура | −60…+85 °C |

Основание: S1, с. 6–16. Значение `vccmin="2.7"` в S4 не следует использовать как разрешение питания 1887ВЕ7Т от 2,7 или 3,3 В: рабочие нормы ТО — 4,5…5,5 В. Также диапазоны регулируемого питания отладочной платы относятся к её возможностям, а не к допустимому питанию данного МК.

При VCC=5,5 В минимальная логическая единица обычного входа равна 3,3 В. Номинальная шина 3,3 В ещё не гарантирует такой VOH под нагрузкой и при разбросе питания. JTAG/ISP подключать на стороне МК +5 В; VTG отладчика брать с этой же шины. Между МК и DDS сохраняется отдельное согласование уровней.

| ISP PDO | PE1 / 3 | Выход данных | ISP_PDO, X1.1 |
| ISP SCK | PB1 / 11 | Вход при программировании | MCU_SCK, X1.3; также такт SPI управления DDS |

Источник распиновки: S1, табл. 2.1, с. 11–14. Состояние соединений: `output/netlist/netlist.xml`, проверено также по контактным площадкам `DDS_47_51.kicad_pcb`.

**ISP PDI/PDO на PE0/PE1 не являются двухпроводным интерфейсом PDI семейства XMEGA.** В программе выбирается ISP (SPI). PB2/MOSI и PB3/MISO используются для обычного SPI; подменять ими PE0/PE1 при программировании 1887ВЕ7Т нельзя.

PEN# не требуется на стандартном 6-контактном ISP при управлении RESET#. Альтернативный вход через PEN# требует специальной последовательности при подаче питания и последующего выключения питания для возврата к работе (S1, с. 314). В проекте сохраняется подтяжка PEN#.

## 5. Программное окружение и отличия от ATmega128

### 5.1. Установка профилей

Описанный изготовителем вариант — AVR Studio 4 или Atmel Studio 6.2. Для Atmel-ICE исходной точкой служит комплект файлов **Atmel Studio 6**. Инструкция для AVR Studio 4 относится к поддерживаемым ею инструментам и не означает поддержку Atmel-ICE этой старой средой.

Для Atmel Studio 6.2, в фактическом каталоге её установки:

1. Скопировать S4 в `devices/1887BE7T.xml`.
2. Скопировать S5 в `tools/Atmel-ICE/xml/1887BE7T_atmel-ice.xml`.
3. Для других используемых инструментов установить соответствующий XML из комплектного каталога `tools`.
4. Перезапустить среду и убедиться, что в Device Programming доступны устройство `1887BE7T`, нужный инструмент и интерфейс.

Типовой путь из РЭ — `C:\Program Files\Atmel\Atmel Studio 6.2\`; на конкретной машине он может отличаться. Автоматическая совместимость этих XML с Studio 7/Microchip Studio и современными пакетами устройств здесь не подтверждена. Если устройство отсутствует в списке, это сначала вопрос установки профиля, а не повод программировать его как обычный ATmega128.

**Создание и компиляция проекта — ATmega128; программирование — 1887BE7T.** Для AVR-GCC это означает целевую архитектуру `-mmcu=atmega128`; `F_CPU` задаётся по реально выбранному такту. HEX нужен для записи, ELF той же сборки — для символов при отладке. S2, с. 31–33; S5.

### 5.2. Память, сигнатура и стирание

| Параметр | Данные комплекта |
|---|---|
| Сигнатура | `1E 97 02` (S1, с. 300; S4) |
| JTAG ID из XML | `0x0970203F`; это ожидаемое значение профиля, не результат измерения |
| FLASH в S4 | `size=0x20000`, `pagesize=0x40`, то есть 128 КиБ и страница 64 байта |
| EEPROM в S4 | `size=0x1000`, `pagesize=0x08` |
| Отличие от комплектного ATmega128.xml | Там FLASH `pagesize=0x100` (256 байт); также отличаются блоки записи ISP и параллельного программатора |
| Стертое содержимое по ТО | Программная память после стирания содержит `0000`; нельзя автоматически требовать AVR blank check на `0xFF` (S1, с. 29, 313) |

Одинаковая сигнатура с аналогом не доказывает взаимозаменяемость алгоритмов. S1, с. 29, прямо описывает страницу в 32 слова (64 байта), что согласуется с S4. Однако табл. 3.124 на с. 302 указывает для RWW 128 слов, для NRWW 32 слова, а алгоритм на с. 314 использует семь младших разрядов адреса. Это **внутреннее расхождение комплекта**. Для штатной работы использовать профиль производителя; для собственного загрузчика, avrdude-конфигурации или алгоритма программирования сначала уточнить геометрию и проверить запись через границы страниц и RWW/NRWW на стенде.

S2, с. 31–33, предупреждает об отличии длительности стирания от ATmega128: снять `Erase device before programming`, записать программу отдельно и входить в отладку без автоматической перезаписи. В старом диалоге JTAG ICE выбран `Don't reprogram`. В другой версии IDE нужно выбрать эквивалентный режим подключения к уже записанному приложению.

Если требуется полное стирание, сначала сохранить нужные данные, выполнить его отдельной операцией и дождаться завершения; затем программировать и проверять. Отключённое автоматическое стирание не означает, что ранее записанная программа или EEPROM уже очищены. Для штатной перезаписи S1, с. 29, допускает обновление памяти без предварительного стирания.

Для разработки собственного алгоритма S1, табл. 3.128, с. 315, приводит минимальные задержки: fuse 4,5 мс; программная память 5 мс; EEPROM 10 мс; Chip Erase 10 мс. S4 задаёт и собственные параметры команд, например ISP eraseDelay=20. Эти числа не отменяют отдельное предупреждение РЭ о работе автоматической цепочки Studio.

### 5.3. Фьюзы и тактирование

Запрограммированный fuse имеет значение **0**, незапрограммированный — **1**. Отображение галочки зависит от программы: сверять прочитанный бит и его смысл. Перед изменением сохранить все три fuse-байта, lock-байт и калибровочные данные.

| Бит | Расположение | Смысл для DDS |
|---|---|---|
| JTAGEN | High, 6 | 0: JTAG разрешён; оставить 0 для отладки |
| OCDEN | High, 7 | 0: встроенная отладка разрешена; требуется при отладке, затем вернуть 1 |
| SPIEN | High, 5 | 0: ISP разрешён; сохранить 0 как резерв доступа |
| CKOPT | High, 4 | Настройка генератора совместно с CKSEL, не универсальное «ускорение» |
| EESAVE | High, 3 | 0: сохранять EEPROM при Chip Erase; выбирать по политике хранения настроек |
| BOOTSZ1:0 | High, 2:1 | Размер загрузочного сектора; не менять без согласованного загрузчика |
| BOOTRST | High, 0 | 1: обычный старт приложения; 0: старт из загрузчика |
| M103C | Extended, 1 | 0: совместимость с предыдущим поколением; для проекта ATmega128/DDS нужен 1 |
| WDTON | Extended, 0 | 0: watchdog постоянно включён; выбирать вместе с прошивкой |
| BODLEVEL/BODEN | Low, 7/6 | Порог и разрешение контроля питания, согласовать с питанием платы |
| SUT1:0 | Low, 5:4 | Задержка старта |
| CKSEL3:0 | Low, 3:0 | Источник и частота такта |

По S1, табл. 3.117–3.119, расчётные заводские байты: **Low=0xE1, High=0x99, Extended=0xFD**. Это расшифровка документа, а не команда записи: конкретный экземпляр, особенно с демонстрационной прошивкой, может иметь другие настройки. В ТО отдельно указано, что SPIEN доступен для записи через SPI; не переносить на него защитные допущения от ATmega128.

Начальные CKSEL=`0001` означают внутренний RC 1 МГц. В текущем проекте предусмотрен внутренний RC **8 МГц**, CKSEL=`0100`; BQ1/BQ2 оставлены свободными. Для 2/4/8 МГц необходимо загружать в OSCCAL соответствующий калибровочный байт: при сбросе автоматически загружается калибровка 1 МГц (S1, с. 300). Сохранить калибровку 8 МГц из адреса 0x0003 и предусмотреть её применение прошивкой; значение индивидуально для кристалла.

SUT=`10` для внутреннего RC соответствует 6 тактам и дополнительной задержке около 130 мс при 5 В (S1, табл. 3.14, с. 53). Не подменять это типовым значением из документации другого AVR. Полные байты для выпуска назначаются после выбора BOD, загрузчика и политики EEPROM.

Для JTAG дополнительно требуется `JTD=0` в MCUCSR. Не отключать JTAG в стартовом коде отладочной сборки и не назначать PF4…PF7 на АЦП/GPIO при активном JTAG. Lock-биты должны разрешать отладку; по S1, с. 262–263, защита блокирует OCD. Снятие защиты стиранием уничтожает защищённую программу.

### 5.4. Начальная скорость и порядок подключения

Для первого подключения к неизвестному экземпляру предлагаются ISP SCK **125 кГц** и JTAG TCK **100 кГц**. Это консервативные стартовые настройки для заводского RC 1 МГц, а не паспортные пределы.

Для ISP S1, с. 313, требует длительность каждого высокого и низкого уровня SCK больше двух тактов ЦПУ при fCPU<12 МГц и больше трёх при fCPU≥12 МГц. При симметричном SCK отсюда следуют fSCK<fCPU/4 и fSCK<fCPU/6 соответственно. При внешнем источнике такта он должен работать и во время ISP.

Microchip для отладки megaAVR требует TCK<fCPU/4 и рекомендует указывать фактический такт цели (S8). Для 1887ВЕ7Т используем это как начальное ограничение инструмента, затем подтверждаем устойчивость связи. Ускорение программирования не следует автоматически переносить на режим отладки.

Последовательность первого запуска:

1. На КФДЛ.301411.243 отключить лишние соединения с периферией, подключить только один программатор/отладчик, выставить допустимое питание МК 5 В. Соединять разъёмы при снятом питании.
2. Для Atmel-ICE выбрать AVR-порт и правильный кабель. Проверить землю, VTG и RESET. Плата цели питается отдельно.
3. В Device Programming выбрать 1887BE7T и нужный интерфейс. Прочитать напряжение, сигнатуру и fuse/lock; сохранить результаты. Чтение сигнатуры ещё не проверяет запись всей памяти.
4. При доступном чтении сохранить демонстрационную программу, EEPROM и калибровку. Стирание не выполнять до сохранения нужных данных.
5. Собрать проект под ATmega128, настроить такт и M103C по выбранному режиму. Не менять одновременно все параметры без необходимости. Смена CKSEL требует повторного подключения на подходящей скорости.
6. Записать HEX профилем 1887BE7T и выполнить чтение/сравнение. При необходимости стирания использовать отдельную операцию, как описано выше.
7. Для отладки обеспечить JTAGEN=0, OCDEN=0, JTD=0 и отсутствие блокирующей защиты. Подключиться без повторной записи, загрузив символы ELF именно записанной сборки. При необходимости включить `use external reset`.
8. Проверить остановку, пошаговое выполнение и аппаратную точку останова. S1 допускает BREAK, но профиль ATmega128 в Atmel-ICE имеет ограничение программных точек останова (S8); их поддержку на этой связке не считать подтверждённой заранее.
9. Зафиксировать версии IDE, драйвера, прошивки ICE, используемый XML, считанные настройки и результат. Затем повторить процедуру на DDS после реализации JTAG.

Если связь не устанавливается: проверить питание 21/52/64, земли, RESET, выбранный интерфейс, такт, скорость и профиль устройства. Отключённый фьюз JTAGEN восстанавливается через доступный ISP; сервисные площадки сохраняют этот резерв. При потере ISP из-за выбора внешнего такта может потребоваться подача такта на BQ1. Если заблокированы оба способа, эти контакты не гарантируют восстановление: остаётся специальный параллельный режим вне этой схемы подключения.

## 6. Использование имеющейся КФДЛ.301411.243

Это отладочная плата с контактным устройством для 1887ВЕ7Т, а не обозначение самого Atmel-ICE. В ней предусмотрены аналог STK500, программатор НИИЭТ КФДЛ.301411.247 и встроенная JTAG-система (S2, с. 20–22). Её удобно использовать для проверки IDE, фьюзов и прошивки до подключения DDS.

Для штатного ISP через STK500 в S2, с. 20, указан шлейф ISP6PIN→7Т-8Т для 64-выводного МК. Для встроенного программатора НИИЭТ используются USB `PROGNIIET`, положение переключателя `ISP` и соответствующий выход ISP, показанный на рис. 41 (с. 33–34). Эти соединения нельзя считать автоматически одинаковыми для обоих программаторов.

Для встроенного JTAG в S2 указаны PROGNIIET, положение `JTAGICE` и JTAG-шлейф. При подключении **внешнего Atmel-ICE** встроенный отладчик/ISP отключить от линий цели. В РЭ прямо описаны внешние JTAGICE mkII и JTAGICE3; для Atmel-ICE использовать S5 и электрическое соответствие контактов S6. Переходник КФДЛ.441461.009 упоминается для mkII и не считается универсальным переходником для любого кабеля.

По S2, с. 23, VTARGET соединяет внутренний регулируемый источник с целью. При внешнем питании цели перемычку источника снимают; земля общая. Не соединять выход питания отладочной платы с работающей шиной +5 В DDS. Для отдельного КФДЛ.301411.247 S3, с. 4, также требует отключить джампер X2 при внешнем питании. Отладочную плату нельзя считать источником питания всего DDS без расчёта нагрузки.

Для ПО КФДЛ.301411.247 включить проверку после записи: в S3, п. 5.13, указано, что при первом запуске автоматический контроль выключен. Установка 3,3 В, доступная у этого программатора, не подходит как штатное питание 1887ВЕ7Т.

## 7. Что остаётся подтвердить

- Работу имеющегося экземпляра КФДЛ.301411.243 и выбранной версии Studio с внешним Atmel-ICE, включая запись/сверку и подключение без перезаписи. XML и руководства изучены; стендовый результат отсутствует.
- Расхождение геометрии страниц S1/S4, если будет собственный загрузчик или сторонний программатор. Штатные XML не редактировались.
- Чертёж корпуса 4203.64-2, формовку и соответствие фактического корпуса текущему посадочному месту. Тип корпуса подтверждён, размеры площадок — пока нет.
- Окончательные fuse-байты и способ загрузки калибровки RC 8 МГц в прошивке DDS.
- Механический доступ к JTAG с установленным корпусом изделия и тип ответного кабеля. Предложение пока содержит электрическую распиновку и ориентировочную область размещения.

# DDS 48–52 МГц · руководство пользователя

**Плата: ревизия F · Прошивка: `dds_fw` 1.0.0 · Обновлено: 6 ноября 2026 года**

Устройство формирует сигнал от **48 до 52 МГц** с шагом **1 кГц**. Частоту задают переключатели S2/S3 и кнопка S4 «Применить». Контроллер 1887ВЕ7Т управляет синтезатором 1508ПЛ8Т по SPI.

Это руководство описывает текущий код из `firmware/`. Работа на физической плате ещё не подтверждена. Проект остаётся предварительным: тип и посадочное место L8 не утверждены, уровень −10 дБм требует калибровки, а прошивка имеет [известные ограничения](#ограничения-текущей-прошивки).

## Подключение и включение

Для текущего варианта нужны источник **+15 В**, внешний источник такта **480 МГц** и измеритель с входом **50 Ом**. G1 пока не является подтверждённым вариантом автономного тактирования.

| Обозначение | Назначение | Подключение |
|---|---|---|
| X2 | Питание | Контакт 1 — +15 В, контакт 2 — GND |
| XW1 | Внешний такт | 480 МГц, проектный уровень 0 дБм на 50 Ом |
| XW2 | Выход DDS | Вход анализатора/измерителя 50 Ом |
| S1 | Выбор источника такта | Замкнут — внешний такт XW1; разомкнут — тракт G1 |
| S2, S3 | Код частоты | 12 разрядов, положение ON означает бит 1 |
| S4 | «Применить» | Короткое уверенное нажатие после изменения S2/S3 |
| X3 | Программирование и отладка | AVR JTAG 2×5, шаг 1,27 мм, внешний Atmel-ICE |
| X1 | Сервисные площадки | Резервный ISP; X1.1 также передаёт UART-лог |

Для уже проверенной и прошитой платы:

1. При выключенном питании подключите X2, источник такта к XW1 и измеритель к XW2. Проверьте полярность X2 по нумерации контактов.
2. Замкните S1 для внешнего такта. Установите нужную частоту переключателями; для первого опыта оставьте все OFF — это 48 МГц.
3. Включите источник такта и питание платы. Прошивка автоматически прочитает переключатели при запуске.
4. Проверьте частоту на XW2. После изменения переключателей нажмите S4.

Оценка потребления при расчётной нагрузке: **0,25–0,30 А от +15 В**, около **3,8–4,5 Вт**. Источник 15 В / 0,5 А даёт запас по установившемуся режиму. Эти значения расчётные; пусковой ток и нагрев измеряются на макете. Первое включение новой сборки выполняет наладчик с контролем шин +5, +3,3 и +1,8 В.

## Переключатели и частота

Каждый переключатель добавляет свой вес к числу **N**. Складываются только положения ON:

**Частота, Гц = 48 000 000 + 1000 × N**, где **N = 0…4000**.

| Переключатель | Вес | Переключатель | Вес |
|---|---:|---|---:|
| S2.1 | 1 | S2.7 | 64 |
| S2.2 | 2 | S2.8 | 128 |
| S2.3 | 4 | S3.1 | 256 |
| S2.4 | 8 | S3.2 | 512 |
| S2.5 | 16 | S3.3 | 1024 |
| S2.6 | 32 | S3.4 | 2048 |

Номера соответствуют схеме и `firmware/src/core/dip_code.h`. Ориентируйтесь на маркировку секций и ON на корпусе, а не на направление «слева направо» на фотографии.

| Частота | N | Включить ON; остальные оставить OFF |
|---|---:|---|
| 48,000 МГц | 0 | Все OFF |
| 48,001 МГц | 1 | S2.1 |
| 49,000 МГц | 1000 | S2.4, S2.6, S2.7, S2.8; S3.1, S3.2 |
| 50,000 МГц | 2000 | S2.5, S2.7, S2.8; S3.1, S3.2, S3.3 |
| 51,000 МГц | 3000 | S2.4, S2.5, S2.6, S2.8; S3.1, S3.2, S3.4 |
| 52,000 МГц | 4000 | S2.6, S2.8; S3.1, S3.2, S3.3, S3.4 |

Например, для 50 МГц: `N = (50 000 000 − 48 000 000) / 1000 = 2000`. Включите указанные секции и нажмите S4. Само переключение DIP не меняет выходную частоту до нажатия кнопки.

### Что делает программа в разных ситуациях

| Ситуация | Поведение текущего кода |
|---|---|
| Включение или сброс МК | Ожидает питание DDS, инициализирует его и читает текущий код DIP |
| Корректный код и нажатие S4 | Дважды читает DIP, записывает и проверяет неактивный профиль, затем переключает DDS на него |
| N больше 4000 | Отклоняет значение; ранее применённая частота сохраняется |
| N больше 4000 сразу после включения | ЦАП остаётся выключенным до допустимого кода и нажатия S4 |
| DIP не успели установиться | Игнорирует попытку; после установки переключателей нажмите S4 снова |
| Обнаружена ошибка связи или проверки DDS | Сбрасывает DDS, ждёт 500 мс и повторяет запуск; на это время сигнал прерывается |
| DDS восстановлен без сброса МК | Восстанавливает последнюю успешно применённую частоту из ОЗУ |
| Питание платы выключено или МК сброшен | Последняя частота не сохраняется в EEPROM; при следующем старте снова читается DIP |

В этой версии нет пользовательского меню, управления частотой с ПК и штатной индикации ошибок на дисплее. UART используется для вывода журнала в Debug, а не для приёма команд.

## Первый запуск прошивки

Краткий маршрут:

**Сборка → Probe → Backup → Read fuses → Write fuses (Debug) → RC 8 MHz calibration → Flash (Debug) → UART-лог.**

Подробное техническое описание находится в [README прошивки, раздел 6](firmware/README.md#6-первое-подключение-платы-новый-1887ве7т). Ниже — последовательность для текущих задач проекта. Успешный первый проход на 1887ВЕ7Т ещё нужно подтвердить на плате.

### 1. Подготовьте редактор и инструменты

Откройте **`C:\Project\DDS\firmware`** в VS Code или Cursor и установите рекомендованные расширения из `.vscode/extensions.json`. Расширения не устанавливают компилятор автоматически: отдельно нужны **CMake 3.21+**, **Ninja**, **avr-gcc с avr-libc и binutils**, **avrdude 7.1+**. Для пошаговой отладки нужен также `avr-gdb`.

Проверьте команды в новом терминале:

```powershell
Set-Location C:\Project\DDS\firmware
cmake --version
ninja --version
avr-gcc --version
avrdude -?
```

Если `avr-gcc` не найден, добавьте каталог `bin` его установки в PATH либо задайте `AVR_TOOLCHAIN_DIR` — корень тулчейна. Для avrdude предусмотрен `AVRDUDE_DIR` — каталог с исполняемым файлом.

Выберите пресет `avr-debug` и нажмите **Ctrl+Shift+B**. В терминале эквивалент такой:

```powershell
cmake --preset avr-debug
cmake --build --preset avr-debug
```

Сборка должна создать `firmware/build/avr-debug/dds_fw.hex` для записи и `dds_fw.elf` для отладчика. Сборка сама по себе ничего не записывает в контроллер.

### 2. Подключите программатор

При выключенном питании подключите **порт AVR Atmel-ICE** к **X3** штатным 10-контактным шлейфом 1,27 мм. Совместите ключ и контакт 1. Плата получает +15 В от собственного источника; **Atmel-ICE её не питает**. VTG на X3 — контроль уровня +5 В цели.

Распиновка X3: 1 — TCK, 2 — GND, 3 — TDO, 4 — VTG, 5 — TMS, 6 — RESET#, 7/8 — не подключены, 9 — TDI, 10 — GND. Это распиновка AVR JTAG.

После подключения включите питание. Для программирования МК внешний такт 480 МГц DDS не нужен; для проверки сигнала на XW2 он нужен.

### 3. Выполните задачи по порядку

Откройте **Tasks: Run Task** через `Ctrl+Shift+P`. Названия ниже соответствуют задачам в папке прошивки.

| Шаг | Задача | Ожидаемый результат |
|---:|---|---|
| 1 | `FW: Probe (сигнатура, напряжение)` | Связь с МК; сигнатура `1E 97 02`, напряжение цели около 5 В |
| 2 | `FW: Backup (flash, EEPROM, фьюзы, калибровка)` | Резервная копия в `firmware/backup/<дата>` |
| 3 | `FW: Read fuses` | Прочитаны текущие fuse- и lock-байты |
| 4 | `FW: Write fuses (Debug: OCDEN=0, H=0x11)` | Записаны настройки Debug; повторным `Read fuses` проверьте L/H/E |
| 5 | `FW: RC 8 MHz calibration → EEPROM` | Индивидуальная калибровка 8 МГц сохранена в EEPROM[0..1] |
| 6 | `FW: Flash (Debug)` | HEX записан, avrdude завершил проверку чтением без ошибки |

Не переходите к следующему шагу после ошибки предыдущего. Для первого подключения оставьте предусмотренный проектом период JTAG `8 мкс` — 125 кГц.

**Особенность нового 1887ВЕ7Т.** По ТО начальное значение Extended fuse — **0xFD**: бит M103C равен 0, включена совместимость с ATmega103. Данная программа собирается для ATmega128. Пресет Debug задаёт **E = 0xFF**, отключая совместимость с ATmega103. Реальное состояние конкретного экземпляра сначала прочитайте: ранее использованный МК может иметь другие настройки.

| Настройка | Debug | Release |
|---|---|---|
| Low fuse | `0x24` | `0x24` |
| High fuse | `0x11` | `0x91` |
| Extended fuse | `0xFF` | `0xFF` |
| Такт МК | Внутренний RC, номинально 8 МГц | То же |
| UART-журнал | Включён | Выключен |
| Сторожевой таймер программы | Выключен | Включён, номинально 1 с |
| JTAG | Программирование и отладка | Программирование; OCD отключён |

Фьюзы выбирают режим тактирования, а OSCCAL уточняет частоту RC. Пустая EEPROM **не доказывает работу на 1 МГц**, если CKSEL уже выбран для 8 МГц. Калибровку выполните до оценки скорости UART; строка `factory 1 MHz` в текущем журнале означает отсутствие сохранённой калибровки 8 МГц, а не измерение частоты ядра.

Обычная цель `flash` использует запись без предварительного стирания и с проверкой. `erase`/`flash_clean` — отдельные операции, их не нужно выполнять при каждом обновлении. Резервную копию храните отдельно: её локальный каталог исключён из Git.

### 4. Проверьте журнал и выход

Подключите **RX USB-UART → X1.1**, **GND USB-UART → X1.6**. Вход RX адаптера должен допускать **5-вольтовый сигнал**. TX и вывод питания адаптера для просмотра журнала не подключаются.

Параметры терминала: **38400 бод, 8 бит, без чётности, 1 стоп-бит, без управления потоком** — 38400 8N1.

Пример нормального запуска:

```text
DDS 48-52 MHz, fw 1.0.0+<git>
[boot] MCUCSR=0x.. OSCCAL=0x.. (EEPROM)
[dds] 1508PL8T ready (DEVID ok)
[app] N=2000 f=50000000 Hz FTW=0x... profile=1
```

`DEVID ok` подтверждает чтение идентификатора, но не измеряет ВЧ-частоту или уровень сигнала. Их проверьте прибором на XW2. При программировании через резервный ISP отсоедините UART-адаптер от X1; при JTAG используется отдельный X3.

## Диагностика и отладка

### Если сигнал отсутствует или не меняется

| Симптом | Что проверить |
|---|---|
| `Probe` не видит МК | Питание +5 В/VTG, порт AVR программатора, ключ X3, настройки JTAG. Начинайте с низкой скорости |
| Сборка прошла, но цели `flash` нет | Наличие avrdude при конфигурации CMake; после настройки PATH выполните конфигурацию снова |
| В терминале пусто | Записана ли Debug, правильный ли COM-порт, RX на X1.1 и общая земля X1.6. Release не выводит лог |
| В журнале нечитаемые символы | 38400 8N1, уровни адаптера, фьюзы тактирования и калибровка OSCCAL |
| `init: error DEVID` | Такт XW1 и S1, питание D1 +1,8/+3,3 В, тракт SPI и обратный сигнал через D4. Это не отдельный датчик отсутствия такта |
| `set_ftw: error VERIFY` | Запись регистров DDS не прошла сверку; проверить линии SPI, питание и фронты SCK |
| `health: error VERIFY` и кратковременный провал сигнала | Проверить помехи SPI и питание; текущая версия перезапускает DDS после одного несовпадения CTR |
| `N=... > 4000 rejected` | Исправить DIP и нажать S4 |
| `DIP unstable, ignored` | Завершить переключение, затем ещё раз нажать S4 |
| Частота верна, амплитуда отличается от −10 дБм | Нагрузка 50 Ом и калибровка `DDS_AMPLITUDE_MUL`; значение 4095 означает почти полную цифровую шкалу, а не гарантированные −10 дБм |
| avrdude сообщает ошибку проверки flash | Сохранить журнал и прочитанные настройки; проверить профиль и размер страницы по документации изготовителя. Не обходить ошибку отключением сверки |

В резервном режиме ISP используется адаптер к площадкам X1. Конфигурацию можно переключить командой `cmake --preset avr-debug -DAVRDUDE_PROGRAMMER=atmelice_isp`; для возвращения к X3 явно задайте `-DAVRDUDE_PROGRAMMER=atmelice`.

### Пошаговая отладка в редакторе

В проекте подготовлен путь **WSL2 + usbipd + avarice + avr-gdb**:

1. Установите среду по [README прошивки, раздел 8.2](firmware/README.md#82-пошаговая-отладка-в-vs-code--cursor-wsl2--avarice--avr-gdb).
2. Откройте `firmware` в WSL; передайте Atmel-ICE в WSL через usbipd.
3. Соберите и запишите Debug. Затем запустите задачу `Debug: avarice server :4242 (Atmel-ICE JTAG)`.
4. Нажмите F5 и выберите `AVR JTAG: Atmel-ICE + avarice`.
5. По завершении остановите отладку и сервер, отсоедините ICE от WSL, если он нужен в Windows.

F5 подключает отладчик к уже записанной программе. После изменения исходников сначала заново запишите HEX и используйте соответствующий ему ELF. Пока ICE обслуживается сервером отладки, не запускайте параллельную запись avrdude.

Работа avarice именно с 1887ВЕ7Т пока не подтверждена. Запасной путь — **Microchip Studio 7**: предварительно записать HEX через профиль проекта, открыть ELF через `Open Object File For Debugging`, выбрать Atmel-ICE/JTAG и **Skip programming**. Это сохраняет разделение: запись — профилем 1887ВЕ7Т, отладка — по ELF. См. [раздел 8.3](firmware/README.md#83-запасной-путь-microchip-studio-7).

### Проверки без платы

Unit-тесты требуют обычного компилятора C для ПК, CMake и Ninja. Из папки `firmware`:

```powershell
cmake --preset host-tests
cmake --build --preset host-tests
ctest --preset host-tests
```

Для simavr сначала соберите Debug ELF, затем выполните в Linux/WSL:

```bash
cmake --preset avr-debug
cmake --build --preset avr-debug
cmake --preset sim
cmake --build --preset sim
ctest --preset sim
```

Нужны зависимости из [раздела 8 README прошивки](firmware/README.md#8-отладка). Не используйте один каталог сборки одновременно из Windows и Linux: пути компилятора записываются в CMake-кэш. Для второй среды используйте отдельную копию или отдельные каталоги сборки с согласованным `DDS_SIM_ELF`.

## Ограничения текущей прошивки

По исходникам версии 1.0.0:

- Проверка CTR выполняется раз в секунду; одно несовпадение вызывает сброс DDS. Пауза 500 мс дополняется временем нового запуска.
- После блокирующих операций накопленные тики обрабатываются как повторные замеры одного уровня. Поэтому заданные 20 мс дребезга кнопки и 10 мс устойчивости PGOOD не всегда означают столько же времени реального наблюдения.
- Потеря PGOOD явно обрабатывается только в `RUN`; во время инициализации немедленное прекращение обмена не гарантируется. Шина +1,8 В отдельно не контролируется.
- Проверка CTR не является полной проверкой всех регистров или фактического ВЧ-сигнала.

Это описание существующего поведения, а не отметка об исправлении. Актуальные [замечания](firmware/REMARKS.md) и [их проверка](docs/FIRMWARE_REVIEW.md) перечисляют дальнейшие работы.

### Что подтвердить на физической плате

| Проверка | Что считать результатом |
|---|---|
| Профиль avrdude `1887ve7t` | Запись и успешная сверка; профиль использует страницу 64 байта по XML, в ТО есть иное указание размера |
| Связь с DDS | Устойчивое чтение `DEVID = 0x0201` и сверка записанных регистров |
| ВЧ-выход | Частоты 48/50/52 МГц, уровень −10 дБм на 50 Ом после калибровки |
| Питание | Токи, нагрев, пуск, поведение PGOOD при снижении питания |
| Отладка | Подключение avarice к 1887ВЕ7Т, остановка и продолжение выполнения |

В README прошивки записаны результаты прежних сборок, unit-тестов и симуляции. При подготовке этого руководства выполнена сверка исходников и документации; сборки и испытания на железе повторно не запускались.
